# 租车协议交互台账 · 在线看板

> 🔗 **在线预览**：https://karry75.github.io/rental-ledger-dashboard/
>
> 一个面向「两轮电动车电池租车」业务的**协议全生命周期管理台账 + 数据看板**。
> 从数据库同步协议与订单数据，自动完成金额核算与分账，并提供多角色协作的录入、审核与导出能力。
>
> ⚠️ 本仓库是**静态只读演示版**，数据已全量脱敏；完整源码见私有仓库 `rental-ledger`。

---

## 一、它解决什么问题

租车业务日常管理存在三类痛点，本系统逐一对应：

| 痛点 | 系统做法 |
|---|---|
| 协议、订单、分成散落在多张 Excel，靠人工搬运 | 统一从数据库（阿里云 ADB）同步，形成单一事实源，一键刷新 |
| 优惠券、退款、分账口径复杂，人工算易错 | 内置 5 个金额列全自动重算 + 6 个订单衍生列（返佣 / 换电服务费 / 双方分账） |
| 门店、业务、财务多方协作，权限与留痕难 | 5 种角色权限模型 + 操作日志 + 编辑叠加层，手工修改不会被同步覆盖 |

业务规模（当前快照）：**204 份租车协议、468 笔套餐订单、10 张业务表、1386 行数据**。

## 二、核心功能

**1. 数据看板**
协议状态分布（已终止 / 生效中 / 已暂停 / 已欠租）、快到期预警、欠租清单、今日开通与今日退订、推广人业绩维度，均实时计算。

**2. 多表台账**
10 张业务表统一浏览：租车用户汇总、套餐购买订单列表、财务看板（订单分成 / 按协议聚合）、车牌号登记、在租用户明细等，支持列顺序自定义。

**3. 查询与筛选**
多维组合筛选（状态、网点、套餐、推广人、日期区间）、全局搜索、排序、冻结表头。

**4. 协作与录入**
车辆登记 / 换车 / 退租三类表单；单元格级编辑走「编辑叠加层」，数据库同步后依然保留人工修改。

**5. 导出**
当前表一键导出 Excel（.xlsx），按筛选结果导出。

**6. 自动化核算**
- 5 个协议金额列：消费总金额、公司实收总金额、累计服务单支付金额、累计服务单退款金额、累计服务单优惠券支付金额
- 6 个订单衍生列：实收分账 → 业务员返佣（15%）→ 换电服务费（分档 129/50/10）→ 扣除后金额 → 双方分账

## 三、在线看板怎么用

打开链接即进入，无需登录（演示版预置只读账号）。

- 顶部切换 **数据表**，左侧为看板与筛选
- 演示版**不支持编辑、保存、数据库同步**——写入操作会被拦截并提示（静态站点无后端）
- 数据快照时间：`2026-09-06 11:38:31`

## 六、技术实现

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | 原生 HTML/CSS/JS（单页） | 无构建、无依赖，直接打开即用 |
| 后端（私有版） | Python 标准库 `http.server` | 静态服务 + 全部 `/api/*` 接口，单文件 `server.py` |
| 数据源 | 阿里云 AnalyticDB（MySQL 协议） | 只读账号，仅 SELECT |
| 同步 | Python + pymysql | `sync_all.py` 六步管线 |
| 存储 | 本地 JSON / JS 文件 | `data.js` 为基准层，`server_edits.json` 为手工编辑叠加层 |
| 静态化 | `static-shim.js` | 拦截 `/api/*` 映射到 `api/*.json`，使看板可脱离后端运行 |

**三层数据架构**：手工编辑叠加层 → 同步基准层 → 前端内存渲染。同步只写基准层，手工修改永不丢失。

## 八、本地运行（需私有仓库源码）

```bash
git clone git@github.com:Karry75/rental-ledger.git
cd rental-ledger
cp sync/db_config.example.json sync/db_config.json   # 填入数据库连接信息
cd 租车协议交互台账
python server.py --port 8081
# 打开 http://127.0.0.1:8081/
```

数据库不可达时，系统自动用本地 `data.js` 兜底运行，不会清空数据。
